# 3-D movement: roadmap

**Status:** approved 2026-10-08. Sub-project C is in progress; E (mode switch), G, F, D (fusion) B1 (running a 3-D project) and B2 (3-D metrics) and A (native 3-D files) are implemented.
**Relates to:** `docs/dev/DECISIONS.md` D-031, `docs/dev/ROADMAP.md` (Z-10),
`docs/tracker-formats/2026-10-07-tracker-import-design.md` (Tier 3)

"Integrate 3-D movement" is four independent projects. Each gets its own spec, plan and
build cycle.

| | Sub-project | Needs first |
|---|---|---|
| **C** | **Side-view depth**: a camera-view setting and a continuous vertical-position metric from ordinary 2-D side recordings | nothing unmerged, no 3-D data |
| **E** | **2D/3D project mode**: `ProjectManifest.mode`, Project-screen choice, lock, 3-D compute blocked. Done; see [the spec](2026-10-09-mode-switch-design.md) | nothing |
| F | **Panel split**: one video with the top and side views in two panels becomes two sessions (a panel rectangle per session, panel-relative coordinates). Done; see [the spec](2026-10-09-panel-split-design.md) | E |
| G | **ID correspondence**: view roles, pairing top and side sessions (regex or by hand), fish mapping between views, a Views step. Done; see [the spec](2026-10-09-id-correspondence-design.md) | E |
| A | Read 3-D tracker files (Anipose pose-3d CSV, DLC-3D). Metrics run on the horizontal plane and z is stored in the project unit. Done; see [the spec](2026-10-10-native-3d-files-design.md). **Amends D-031 a second time** | `feat/native-units` merged |
| B1 | **Run a 3-D project**: run units per fused pair, IL-15 from the fused depth, depth in the exports, UI and CLI. Done; see [the spec](2026-10-10-3d-run-design.md) | D |
| B2 | Metrics that use z: 3-D speed and path length, 3-D neighbour distance. Done; see [the spec](2026-10-10-3d-metrics-design.md). **Amends D-031** | B1 |
| D | Fuse top and side recordings into one 3-D session. Done; see [the spec](2026-10-09-fusion-design.md) | F and G (done) |

**Order: all sub-projects are done.** C went
first because no data of any kind existed, it is testable on synthetic tracks, and it created the
project-level camera-view setting that B reuses.

## Hand-offs between the sub-projects

- `KeypointSelection.plane` and `camera_view` have no defined precedence. A and B must define
  a vertical axis for 3-D data.
- The `has_pixel_frame` guard from native-units joined the IL-3 and IL-14 arena fallback in A (the data extent is used, with a warning).
- Per-session camera views arrive with D (`Engine.camera_view_for(session)` is the seam).
- IL-3 and IL-14, which assume a top-down view, are gated for side views (D-045); an unset view keeps
  both.
