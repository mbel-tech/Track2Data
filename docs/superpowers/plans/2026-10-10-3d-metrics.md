# 3-D Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three metrics for fused 3-D sessions — IL-16 3-D path length, IL-17 3-D speed, GL-16 3-D nearest-neighbour distance — with availability rules (fused session and top-view cm scale required), exports, documentation and tests.

**Architecture:** One small helper module builds the (X, Y, Z) cm positions of a fused session or reports why it cannot. The three metrics use it. A class flag plus the existing availability module decide, at manifest level and per run unit, whether a 3-D metric may run, and say why when it may not. Everything else (exporters, README, Metrics screen, binning) reuses the existing metric machinery.

**Tech Stack:** Python 3.11+, numpy, scipy (`cKDTree`), pandas, PySide6 (Metrics screen rows), pytest, ruff, mypy.

**Spec:** `docs/3d-movement/2026-10-10-3d-metrics-design.md` (also read the B1 spec `docs/3d-movement/2026-10-10-3d-run-design.md`, and D-040/D-041 in `docs/dev/DECISIONS.md`).

## Global Constraints

- Positions in cm: `X = xy[...,0] / px_per_cm`, `Y = xy[...,1] / px_per_cm`, `Z = depth * depth_height_cm`, from the fused `PreprocessedSession` (`xy`, `depth`, `px_per_cm`, `depth_height_cm`). A session without `depth`, `px_per_cm` or `depth_height_cm` has no 3-D positions: the helper returns `None` and the metrics return their full column set filled with NaN (never 0), with no RuntimeWarning (tests run with `-W error::RuntimeWarning`).
- A step (IL-16) needs finite X, Y, Z at both of its frames. A frame (GL-16) needs finite X, Y, Z for every fish. Separator rows in a fused session carry NaN so they drop out naturally.
- Body length in cm for animal `k` = `psess.body_length_in_px()[k] / px_per_cm`; NaN when unknown (the `_bl` columns are then NaN).
- Metric IDs and exact columns:
  - IL-16 (`name="path_length_3d"`, `label="3-D Distance Travelled"`, individual, `requires_identity=True`, `priority="optional"`): `session_id, metric_id, individual_id, path_length_3d_cm, path_length_3d_bl, n_valid_steps`. No valid step → `path_length_3d_cm`/`_bl` NaN, `n_valid_steps` 0.
  - IL-17 (`name="speed_3d"`, `label="3-D Speed (mean / median / max)"`, individual, `requires_identity=True`, `priority="optional"`): `session_id, metric_id, individual_id, mean_speed_3d_cm_s, median_speed_3d_cm_s, max_speed_3d_cm_s, mean_speed_3d_bl_s`. Per-frame 3-D speed = `sqrt(vh**2 + vz**2)` with `vh = kinematics.speed_px_s / px_per_cm` and `vz` the vertical speed in cm/s from `compute_kinematics` (same estimator and config the pipeline used) applied to the series `Z` (pass an `(n_frames, n_animals, 2)` array `[Z, 0]`; its `speed_px_s` is `|vz|`); valid where both are finite.
  - GL-16 (`name="nearest_neighbour_distance_3d"`, `label="3-D Nearest-Neighbour Distance"`, group, `requires_identity=False`, `priority="optional"`): `session_id, metric_id, mean_nnd_3d_cm, median_nnd_3d_cm, mean_nnd_3d_bl, n_skipped_frames`. One fish → NaN statistics, `n_skipped_frames` = number of frames. `mean_nnd_3d_bl` uses the same body-length convention as GL-1's `mean_nnd_bl` (read GL-1), converted to cm.
- Availability: new class flag `Metric.requires_depth_scale: ClassVar[bool] = False`, True on the three. Reasons (exact texts): 2-D project → `"needs a fused 3-D session"`; 3-D project at manifest level with `calibration.mode == "bodylength"` → `"needs a cm scale for the top view (use scalar or session calibration)"`; run time, per fused unit with `px_per_cm is None` or `depth_height_cm is None` → `"needs a cm scale for the top view"` (recorded in the run README's skipped-metrics list like other skipped metrics). Available otherwise. Other metrics' availability is unchanged.
- 2-D behaviour and every 2-D output stay byte-identical; the new metrics are not available in 2-D. `window_safe` follows the 2-D counterpart (IL-16, IL-17, GL-16 compute per bin like IL-1, IL-2, GL-1).
- Every metric has a `MetricDocumentation` (definition, formula, inputs, assumptions, warnings, citation: "Standard kinematics" for IL-16/IL-17 and the GL-1 reference for GL-16), a `docs/METRICS_SPEC.md` section and a `docs/METRIC_REFERENCES.csv` row, in the existing format; `tests/test_metric_references_consistency.py` and `tests/test_references_resolve.py` must pass.
- CI also runs `mypy` (mypy 2.4.0, numpy 2.4.6; a throwaway venv reproduces it) and `ruff check .`: run both before each commit; 3 pre-existing unused-ignore errors in `track2data/readers/` are local noise. Lambdas capturing `self` on a widget's child use `ui/widgets/weak_slot.py`.

## Review Focus

- A fish with gaps in x, y or depth, an all-NaN fish, one fish, a zero-length track and an unknown body length / tank height / scale give NaN without warnings, never 0 and never an exception (Tasks 1-4).
- A 3-D metric is never offered or computed for a session without depth or without a scale, in the engine, the Metrics screen, `validate`, the CLI and the README skip list (Task 1).
- IL-17's horizontal part is exactly IL-2's speed and `3-D speed >= IL-2 speed` for the same frames (Task 3).
- Binned runs give per-bin values consistent with a whole-session run (Tasks 2-4).
- 2-D runs and the existing metrics are unchanged (all tasks).
