# Fusion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a matched top/side pair of sessions into one fused session (the top view plus a depth array and an agreement report), with per-pair settings, an engine entry point, and a Fusion panel and dialog on the Views page. 3-D compute stays blocked.

**Architecture:** A pure, Qt-free package `track2data/fusion/` takes two `PreprocessedSession`s, the pair's `FusionSettings` and a `same_video` flag, aligns them on video frames, computes depth from the side view's y, and reports how well the shared horizontal axis agrees. `Engine.fuse_pair` preprocesses both sessions through the existing cached path and calls it. The store holds the settings on the `ViewPair`; the Views page shows a status and opens a dialog with a side-view preview and two draggable lines.

**Tech Stack:** Python 3.11+, numpy, pydantic v2, PySide6, pytest / pytest-qt, ruff.

**Spec:** `docs/3d-movement/2026-10-09-fusion-design.md` (also read the F, G and C specs it builds on).

## Global Constraints

- `FusionSettings(frame_offset: int = 0, horizontal_axis: Literal["x","y"] = "x", flip: bool = False, surface_row: float, floor_row: float, tank_height_cm: float)`; finite numbers only; valid when `0 <= surface_row < floor_row` and `tank_height_cm > 0`. `ViewPair.fusion` defaults to `None`; manifests without it load unchanged.
- Depth `d = (y_side - surface_row) / (floor_row - surface_row)`; 0 = water surface, 1 = tank floor. Values outside `[0, 1]` become NaN and are counted in `FusionReport.n_outside_column`; never clipped.
- Side scale `side_px_per_cm = (floor_row - surface_row) / tank_height_cm`. Top scale is the top `PreprocessedSession.px_per_cm`.
- Alignment is on video frame numbers (`PreprocessedSession.timeline()`): side frame = top frame + `frame_offset`. Rows flagged in `separator_mask` are never fused. In `same_video` mode the offset is forced to 0.
- Frame rates (`session.video.fps`) that differ by more than 0.1% (relative) raise `FusionError`.
- Only fish in the pair's `fish_map` are fused (top labels via `fish_labels`); the fused animal order follows the top view. Validation reuses `validate_fish_map`; an empty map, any message from it, or an identity-free session raises `FusionError`.
- Agreement: both views in cm, side horizontal position compared with the chosen top axis (negated when `flip`), the median difference removed per fish, RMS (cm) reported per fish and overall (RMS over all fused samples). Warning when overall RMS exceeds 10% of the pooled range (max - min) of the top axis in cm. Without top `px_per_cm`: `agreement_skipped = "top view not calibrated"`, depth still computed.
- `suggest_offset`: lags in `[-window, +window]` frames with `window = round(5 s * fps)`; returns the lag with the lowest overall RMS if it is at least 20% lower than the lag-0 RMS, else `None`.
- Fusion is not cached on disk: both inputs come from `Engine.preprocess_ref`, which is cached; the numpy step is cheap. (Spec deviation: Task 9 edits the spec.)
- `Engine.require_computable()` and the 3-D compute block are unchanged.
- Lambdas capturing `self` on a widget's own children use `ui/widgets/weak_slot.py`; a page rebuild never calls the store's write methods; heavy work runs on `store.tasks` with stale results ignored (follow `ui/widgets/panels_section.py`).
- No change to 2-D behaviour or to sessions without fusion; the existing suite must pass. Run `ruff check` on touched files before each commit.

## Review Focus

- A pair whose sessions share no frames, or whose offset pushes the overlap to zero, gives a clear `FusionError`, not an empty array crash (Tasks 2, 4).
- Gaps (NaN) in either view propagate to NaN depth / NaN agreement samples; an all-NaN fish has `None` RMS, never a divide-by-zero or a NaN warning storm (Tasks 2, 3).
- Rows inserted for unobserved video (`separator_mask`, `tracked_mask`) are never fused or counted as overlap (Task 2).
- A top view with a different animal order than the side view fuses by label through `fish_map`, not by index (Task 2).
- Changing the settings or the offset recomputes (no stale result); a removed/renamed session or pair gives a message, not a traceback (Tasks 4, 8).
- Surface/floor rows outside the side frame or inverted never produce a result; the dialog disables OK (Tasks 1, 7).
