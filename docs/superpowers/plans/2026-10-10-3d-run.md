# Running a 3-D Project Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a 3-D project run: every fusable top/side pair becomes one run unit that goes through the existing pipeline as a fused session, IL-15 reads the real depth, the exports carry the depth, and the UI/CLI stop blocking 3-D projects that have at least one fusable pair.

**Architecture:** `Engine.run_units()` builds a `RunPlan` (units + skipped sessions with reasons): one unit per session in 2-D, one per fusable pair in 3-D. `run()` iterates the plan; a pair unit takes its `PreprocessedSession` from `Engine.fuse_pair` instead of import + preprocess, everything after that is the same code. `require_computable()` and `compute_metrics()` enforce "fused sessions only" in 3-D. IL-15 and the exporters read `psess.depth`.

**Tech Stack:** Python 3.11+, numpy, pandas, pydantic v2, PySide6, pytest / pytest-qt, ruff, mypy.

**Spec:** `docs/3d-movement/2026-10-10-3d-run-design.md` (also read the fusion spec `docs/3d-movement/2026-10-09-fusion-design.md`, and D-037/D-040 in `docs/dev/DECISIONS.md`).

## Global Constraints

- Run unit ids: a 2-D unit is the session id; a 3-D pair unit is `f"{top_session_id}+{side_session_id}"` (the id `fuse` already gives its `FusedSession`). Output folder `out_dir / unit_id`.
- A pair is **fusable** when it has `fusion` settings and `Engine.fuse_pair(pair)` returns without `FusionError`. Skip reasons (exact texts): `"not in a fusable pair"` for a session with no pair; `"pair {top}+{side}: no fusion settings for this pair"`; any `FusionError` text prefixed `"pair {top}+{side}: "` for a pair that does not fuse; the sessions of a skipped pair are listed once each with that pair's reason.
- `Engine.require_computable()` in a 3-D project raises `ValueError` when the plan has no units: message `"no pair is ready to fuse: " + "; ".join(first three skip reasons)`; when the project has no sessions or no pairs at all the message is the existing `MODE_3D_BLOCK_REASON` ("3-D fusion is not available yet" is reworded to `"Pair and fuse a top and a side session first"`; update the constant and every test that quotes it).
- In a 3-D project `compute_metrics(psess)` raises `ValueError("3-D projects compute fused sessions only")` when `psess.depth is None`; `run_session(session, ...)` raises `ValueError("use run() for a 3-D project")`. `sensitivity` keeps refusing 3-D projects with `"sensitivity is not supported for 3-D projects yet"`.
- IL-15 on a session with `depth` set: per animal mean, median, SD (ddof 1) of the depth fraction over finite samples; `mean_depth_cm = mean * psess.depth_height_cm` (NaN when `depth_height_cm` is None); `frac_outside_extent = psess.depth_outside[k] / (n_finite_side_samples_k)` where `depth_outside` (per animal, counts) comes from `fuse` and the denominator is `depth_outside[k] + count of finite depth values for animal k`; `depth_extent_source = "fusion"`. No zones involved. With no depth, IL-15 behaves exactly as before.
- Availability: a metric with `uses_depth = True` (IL-15 only) is available when the session has depth OR the camera view is in its `valid_camera_views`; fused sessions are top-view for every other metric (`Engine.camera_view_for` returns `"top"` for a fused session).
- Exports: per-frame tables get `depth_fraction` and `depth_cm` (cm = fraction * `depth_height_cm`, NaN when unknown) only when the session has depth; position columns, row order and everything else unchanged; 2-D outputs byte-identical to before (existing fixtures/tests are the guard).
- Provenance (sessions.csv columns and per-session README rows, only for pair units): `unit_kind`, `top_session_id`, `side_session_id`, `fusion_frame_offset`, `fusion_axis`, `fusion_flip`, `fusion_surface_row`, `fusion_floor_row`, `fusion_tank_height_cm`, `fusion_overlap_frames`, `fusion_fused_fish`, `fusion_unmatched_top`, `fusion_unmatched_side`, `fusion_outside_column`, `fusion_agreement_rms_cm`, `fusion_agreement_warning`, `fusion_agreement_skipped`. Run-level skipped sessions: a `skipped_sessions` table in the run README and rows `session_id,reason` in a new `skipped.csv` (written only when something was skipped).
- Fused sessions are not written to the preprocessing cache. A serial run reuses the plan's fused result; a parallel worker fuses again from the manifest.
- Lambdas capturing `self` on a widget's child use `ui/widgets/weak_slot.py`; page rebuilds never write; CI also runs `mypy` and `ruff check .` — run both before each commit (3 pre-existing unused-ignore mypy errors in `track2data/readers/` are known local noise).
- No change to 2-D behaviour; the existing suite must pass.

## Review Focus

- A 3-D project where every pair fails to fuse refuses cleanly in every entry point (engine `run`, `compute_metrics`, `export`, CLI, UI status), never a traceback (Tasks 3, 4, 6).
- One bad pair among good ones does not abort the run: it is skipped with its reason and the others run (Tasks 3, 4).
- Parallel and serial runs produce identical files (Task 4, Task 7).
- NaN gaps, an all-NaN animal and an unknown tank height give NaN, not warnings or crashes, in IL-15 and the exported depth columns (Tasks 2, 5).
- 2-D runs are byte-identical: no new column, row or file appears (Tasks 4, 5).
- A session removed or renamed while a plan is shown does not crash the status or the setup check (Task 6).
